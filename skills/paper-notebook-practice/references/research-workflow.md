# 从资料与互联网到可靠试卷

当前 Agent 负责研究、出题与解答；本项目负责保存证据、检查结构、组卷和交付。直接使用当前 Codex、Claude Code、网页会话等环境已有的附件、联网、视觉及代码能力，不需要另接模型 API。所有可执行工作由 Agent 完成。

## 1. 先识别，再决定研究路径

阅读实际附件和用户要求，先确认资料是什么，再确定任务是什么。识别结果包含：考试或课程、年度、国家/地区/院校、科目代码、专业方向、层级或年级、知识进度、题型、难度、目标成品，以及资料是否有题、有答案、有图、有缺页。不要从文件名直接推定全文内容。

按 [exam-routes.json](exam-routes.json) 选 `authoring.routeId`，按 [authoring-profiles.json](authoring-profiles.json) 组合 `profileIds`。数一组合高数、线代、概率统计；数二只组合高数和线代；199组合数学基础、逻辑与写作；408组合算法和系统。工程资格还须识别基础/专业、知识/案例、一级/二级与专业方向。多个目标分别建立路线，不将“数一与数二”悄悄归到其中之一。国际课程、海外升学、日语等语言证书、入籍、艺术与音乐按[国际命题方法](global-exams-authoring.md)识别版本、考试形式、component与作答证据；[任务模式库](question-pattern-library.md)将真实任务映射到现有六类题型。

**路线、完整规格、版式分别确认。** 路线决定解题方法，`exam.specification` 决定完整试卷的题组/题量/时长/分值，`presentation` 和模板决定纸面。路线注册不代表所有考试年份的规格已经核定。官方招生或报名通知可以核对科目身份；只有细则、完整原卷或明确的大纲才能支持具体题量与分值。

## 2. 落实资料边界

默认 `sourcePolicy.mode: uploads-first`，`questionPreference: originals-first`。用户已指定“只能用这些文件”“用这本书某章节”“不要用旧版”，直接保存并执行；无需再次确认。

| 策略 | 实际行为 |
| --- | --- |
| `uploads-only` | 只使用允许的上传资料；允许当前 Agent 独立解答、基于它改编或新编。禁止从网上或记忆里补进未受资料支持的事实、公式、法条或答案依据。 |
| `uploads-first` | 先检索允许的用户资料；只为实际缺口补充互联网材料。 |
| `open` | 可结合上传与网络材料，仍保留指定来源、排除项和版本。 |

`requiredMaterialIds` 是必用资料，`allowedMaterialIds` 是允许范围，`excludedMaterialIds` 是排除项。实际阅读后将用户文件名映射为材料 ID，不能用文件名假装 ID 已存在。`requiredVersions` 记录 `{materialId,version}`，例如用户指定的规范版本。新编材料 `provenance.kind: authored`，`derivedFrom` 指向实际依赖的资料；不得复制排除资料到新材料绕过限制。

`originals-first`：先用范围和难度匹配的原题、完整题组，再改编，最后补编。原题并非“网上看起来像真题”的题目；机构回忆、编辑整理、二次改写分别保留身份。用户要求原创时可用 `generated-first`。全量题库按资料覆盖组织，不能因偏好原题而遗漏讲义里的有效任务。

## 3. 建立资料索引与缺口表

为每份材料保留文件名/标题、SHA-256（本地文件）、出版机构、版本、日期、页码、Block ID、原始文字和图表。网络材料保存实际 URL、发布机构、发布日期、获取日期、来源类型与许可；正文、图片或 PDF 未读取前不引用搜索摘要作为答案依据。

先制作简短缺口表，再按表研究：

| 缺口 | 先查哪里 | 达到什么即停止 |
| --- | --- | --- |
| 考试身份/版本 | 用户原件 → 目标年度主管部门/院校公告 | 身份、版本与适用范围明确 |
| 题组/计分/时长 | 当期大纲、完整原卷、评分说明 | 能逐项核对完整规格 |
| 原题缺页/图表 | 同一原文件、官方附件或可核对的完整扫描 | 题干、共享材料和全部选项齐全 |
| 缺参考答案 | 官方答案/勘误 → 独立求解 → 可信解答对比 | 得到可重算结果及依据 |
| 工程规范 | 考试指定目录、规范正文、勘误与效力状态 | 版本、条文、参数和适用条件可定位 |
| 题库不足 | 已允许教材/讲义/原题 → 缺口检索 → 补编 | 蓝图覆盖达到目标，无重复凑数 |

检索式应包含明确身份与缺口，例如“2027 江苏 公务员 A类 申论 大纲”“目标院校 年度 科目代码 考试大纲”“规范编号 版本 勘误 条款”。以官方/院校/原出版物为第一层，可信完整副本为第二层，培训讲解作解答线索。标记转载身份，不把高校转载的国家公告写成该高校制定的大纲。

检索记录写在 `job.quality.notes` 或独立 `research-log.md`：查什么、查到什么、实际读取哪一段、解决哪个缺口、是否有冲突。不是每题都要联网；上传已充分且用户限制资料时直接研究上传内容。遇到联网不可用，继续可完成的整理与求解，仅保留依赖网络的具体缺口。

## 4. 从蓝图到题目

先建立“知识范围 → 能力 → 作答证据 → 任务 → 评分”的蓝图，并以分值和预计作答时间衡量覆盖。`authoring.blueprint[]` 可记录 `id/knowledge/ability/types/count/points/estimatedMinutes/sourceIds`。`question.assessment` 记录实际知识点、能力与难度理由。预期难度用所需步骤、抽象和迁移解释；没有试测数据时不用正确率假装实测。

数学必须真的计算、证明、讨论参数或建模；申论必须对给定资料作概括、分析、执行或论证；工程必须从条件、图纸、工况和规范得出计算或决策。定义回忆题可用于必要基础，但不能取代目标学科主体能力。按相应专题阅读：[考公](civil-service-authoring.md)、[考研](postgraduate-authoring.md)、[工程](engineering-authoring.md)。

## 5. 答案与证据一起制作

每题 `source` 指向实际题目或知识依据，`source.exact` 是材料内连续可定位原文。`supportingSources` 以 `question/knowledge/answer/standard` 区分题源、知识、答案与规范；不能用一处题干来源假装证明答案正确。`answerProvenance.kind` 分别使用 `official/third-party/independent`，独立答案即使与机构答案一致也不改称官方答案。

先独立解，再读已有答案比对；若原题答案已在同一页看到，采用另一算法、边界/反例或可复算程序进行独立复核。求解失败或来源冲突保留 `needs-review` 与具体原因，不删掉难题、改动原题条件或编造正确答案。

主观题提供 `rubric.criteria`：每点描述可观察的步骤、材料证据或结论与分数，合计等于题分。`equivalentMethods` 接受有效替代解法，`tolerance` 说明数值误差。申论要点附材料依据，开放作文另给档次说明，工程答案附公式、代入值、单位、版本与条款。范文不是评分标准本身。

`verification.checks` 写实际做过的方法、输入/推理和结果。例如“代回原方程后两侧均为…”，“用材料2第3段验证要点…”，“独立按条款…重算…”。若全部完成才写 `status: verified`；失败或未解决项如实保存。`authoring.requireVerification: true` 要求交付数据具有这些记录。

**结构校验与学科判断的边界：** CLI 能检查引用存在、`exact` 连续匹配、来源权限、资料派生关系、指定版本、评分合分以及核验状态/记录；这些检查不能自动证明数学推导、法律适用、语义等价或申论质量。当前 Agent 必须实际演算、读条文、回材料、比对选项，并记录结果。不能为了通过结构校验填入虚假的“已验证”。

## 6. 闭合交付

解决实际内容问题后执行项目验证、组卷、构建与文件核对；打开题目卷、答案卷和答题卡。核对共享材料、题号、公式图形、字号、真实边距、分页、作答空间和打印。主观长答、申论字格和工程步骤区按实际任务设计。真实原卷版式依原件实测，不能凭科目名添加不存在的密级或校徽。

交付可复用题库、独立答案与评分和用户选择的纸面文件。将来源索引、研究与核验记录留在作者源或附加说明，考生纸面只呈现正式任务，不混入内部检索、AI制作或“选编/重组”等标签。代码保持 MIT 免费本地使用；第三方题源与规范保留各自权利。

## 彩色与实际表现证据

图表若仅用颜色编码，提供文字、形状或纹理及核对过的灰度替代；颜色决定答案时保存`colorRequired`并保留彩印。灰度替代图、参考答案和评分需一起检查。口语、实验、作品和演奏保存实际音视频、过程或产物，不以任务纸和自述记录代替已执行证据。动态公民知识答案、考试结构更新与作品/录音权利在对应材料记录来源、日期及适用范围。
